### 5.6 Target receives SIGCONT and resumes after cpulimit exits

| field | value |
|-------|-------|
| helper | `/tmp/cpulimit-baseline/ignint_timed` (ignores SIGINT, burns CPU for 2s wall-clock, then exits 0) |
| command | `./src/cpulimit -l 50 -v -- /tmp/cpulimit-baseline/ignint_timed` (run in background) |
| probe | after ~0.8s send `SIGINT` to the cpulimit PID; poll child state and `/proc/<pid>/stat` utime/stime |
| expected | child transitions to running (R), CPU ticks keep increasing (not left stopped/T); cpulimit exits 0 |
| measured | pre-SIGINT state `R`, utime=67 ticks; post-SIGINT polled states `R R R R` then child self-exited; cpulimit printed `Process ... exited with status 0`; cpulimit exit 0 |
| confidence | high |

The child ignoring SIGINT isolates the resume path: the forwarded SIGINT does not kill it, so the only way it keeps accumulating CPU after the quit is that cpulimit's exit path delivered `SIGCONT` (see `limit_process.c:422` and `limiter.c:745`).

No standalone probe was constructed for this baseline; the existing unit tests (`test_seam_*`, valgrind 117 rounds) cover the bookkeeping.
- `reap_all_by_name` cleanup is exercised implicitly by the unit/valgrind suite; no separate manual probe was run.
